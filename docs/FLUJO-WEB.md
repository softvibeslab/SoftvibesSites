# Proceso para crear un sitio

## 1. Identidad y encargo
Lee el brief: oferta, audiencia, región, idioma, objetivo y acción principal. Recoge materiales
propios o autorizados. Distingue hechos confirmados de hipótesis y pendientes. Define un responsable.

## 2. Inventario y elección de base
Aplica landing-inventory-first antes de diseñar. Actualiza el inventario del workspace receptor,
compara nichos y revisa bases autorizadas. Reutiliza selectivamente estructuras del mismo nicho
sin transferir datos. Cuando sea nuevo, investiga fichas actuales de Envato y documenta candidatos,
stack y licencia. Comprar o incorporar un paquete comercial requiere autorización/licencia.
El paquete llega con inventario vacío: no contiene ni demuestra bases previamente desarrolladas.

## 3. Investigación y contenido
Documenta fuentes, fecha y evidencia de los problemas de conversión. Define jerarquía de mensajes,
secciones, CTA y estructura SEO. No conviertas propuestas, testimonios de ejemplo o cifras de
terceros en afirmaciones del negocio. Mantén análisis internos fuera del sitio público.

## 4. Dirección visual y arquitectura
Elige tipografía, color, espaciado, imágenes y estados responsive con intención. Usa imágenes
pertinentes, licenciadas, optimizadas, con dimensiones y texto alternativo. Evita placeholders
en una entrega final. Elige HTML estático, Astro u otro stack según mantenimiento y necesidades;
no impongas un framework por el ejemplo de una skill. Confirma si hace falta CMS, bilingüismo,
catálogo, formularios, reservas o pagos antes de construirlos.

## 5. Implementación
Construye en el proyecto designado. Incluye estados vacíos/error/carga y validación de entradas.
Los formularios deben tener destino real, mensajes claros y protección según el contexto. Si hay
CMS: autenticación, autorización, validación de archivos y protección del editor; las claves nunca
van al navegador. Usa variables de entorno y documentación sin secretos.

## 6. Verificación
Prueba navegación, CTA y formularios; enlaces internos; móvil/escritorio; teclado y foco;
contraste y texto alternativo; metadatos; ausencia de datos del cliente fuente; build/pruebas
apropiadas. Comprueba la conversión desde una visita inicial hasta el resultado esperado.
Documenta qué se comprobó realmente, qué depende de servicios y qué queda pendiente.

## 7. Entrega y publicación
Entrega archivos, instrucciones, validación y requisitos. Publica únicamente con autorización
explícita, destino confirmado y paquete completo revisado. Revisa alcance y comportamiento del
proveedor antes de desplegar; no asumas que un deploy parcial conserva archivos del servidor.
Verifica las rutas afectadas después de publicar. Actualiza inventario y documentación con el
estado real. Enviar mensajes o materiales a terceros requiere autorización independiente.
